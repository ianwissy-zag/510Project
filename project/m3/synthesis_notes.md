My current design uses AXI stream for communication, a weight stationary systolic array for compute, along with a 9 stage GELU pipeline fused to the output for forward pass multiplication. I have two different functioning implementations, a 16x16 systolic array that uses a 256 bit AXI bus for data transfer, and a 32x32 systolic array that uses a 512 bit bus. My design uses a predictive 7nm PDK known as ASAP7, and was synthesized using the cadence tool chain, more specifically using Genus. 

My design has evolved over time. Initially, I implemented a simple, vectored MAC version of the accelerator with 128 MACs in parallel to manage the vector multiplication. I determined that this implementation did not provide sufficient speedup, so I re-synthesized with a 512 MAC version. This provided improved speedup, but with the overhead of requiring data wires to each of the mac units, which significantly increased die size and synthesis time. I eventually determined that in the backwards pass matrix multiplication, one of the matrix dimensions was 768, which would have resulted in significant wasted bandwidth (up to one quarter) since the dimension does not divide evenly into vectored MAC width. This prompted me to transition to a systolic array implementation. My initial systolic design was a 16x32 implementation, to match the number of MAC units in the 512 vectored implementation. I ultimately decided to implement both a 16x16 and a 32x32 version to have a choice between size/power consumption and performance. The final change I made was to include GELU and bias calculations in the design, as the data was already present, resulting in near infinite speedup for those portions of the algorithm. 

The current designs (32x32 and 16x16 with fused GELU) both synthesize cleanly except for a ~1ps negative slack time on a 1650ps clock for the 32x32 implementation. The critical path for this negative slack is in the GELU pipeline, consisting of a BF16 multiplier followed by a BF16 to FP32 accumulator. I may re-synthesize this design either with the constraint relaxed 1ps (a negligible performance loss) or with additional rounds of timing closure in order to optimize away the problem. I may also consider this negative slack acceptable, given how small it is compared to the clock period. The final solution would be to pipeline the critical path, but this feels like overkill to me, due to the minuscule size of miss, and because my systolic array consists of the same structures, and timing closure was achieved for it. 

The ASAP7 PDK I used does not contain SRAM cells, only flip-flops. Therefore all SRAM in my design were synthesized as flip-flops. This resulted in a significant power and size overhead, given that flip-flops are implemented with 20 flip flops rather than 6 for SRAM cells. It is estimated that replacing flip-flops with SRAM would reduce the power and size of my chip by approximately 40%. This is unfortunate, but given that the cost is estimable, it is not difficult to determine what the true size and power consumption of my chip would be with a more robust PDK. I may try re-synthesizing with a different PDK, but this would require a complete rethinking of my constraints and, since the transistor size would not be constant, would still only provide an estimation of the cost of SRAM vs flip-flops.
